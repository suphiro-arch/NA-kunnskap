Evne til å understøtte datadeling og tjenesteintegrasjon ved å oppdage, forstå og koble seg til tilgjengelige data via en standardisert oversikt over maskinlesbare grensesnitt (API-er). ### Begrunnelse (Hvorfor) Kapabiliteten gjør det mulig for virksomheter å finne, forstå og ta i bruk tilgjengelige API-er for datadeling og tjenesteintegrasjon. Den løser problemet med at maskinlesbare grensesnitt ofte er spredt, ulikt dokumentert eller vanskelige å oppdage, noe som hindrer gjenbruk og fører til unødvendige spesialintegrasjoner. ### Hva det innebærer (Omfang) - **Juridisk (Middels vekt):** API-beskrivelser må synliggjøre tilgangsvilkår, behandlingsgrunnlag, bruksbegrensninger, ansvar og eventuelle krav til avtaler eller godkjenning. - **Organisatorisk (Høy vekt):** Etablere rutiner for å registrere, kvalitetssikre, publisere og vedlikeholde API-beskrivelser, med tydelig ansvar hos API-eier og tjenesteeier. - **Semantisk (Høy vekt):** Beskrive API-er med standardiserte metadata, begreper, formål, datainnhold, endepunkter, status, versjoner og relasjoner til datasett, tjenester og hendelser. - **Teknisk (Svært høy vekt):** Tilgjengeliggjøre API-oversikten gjennom kataloger, søkefunksjoner og maskinlesbare spesifikasjoner, for eksempel OpenAPI, slik at utviklere og systemer kan koble seg til på en standardisert måte. ### Bidrag til sammenhengende tjenester og felles økosystem Kapabiliteten bidrar til sammenhengende tjenester ved å gjøre det enklere å finne og bruke eksisterende grensesnitt for datadeling og integrasjon. Når API-er er dokumentert og tilgjengelige i en standardisert oversikt, kan virksomheter raskere koble tjenester sammen uten å bygge nye punkt-til-punkt-integrasjoner. For det felles økosystemet gir kapabiliteten bedre gjenbruk, lavere integrasjonskostnader og mer forutsigbar teknisk samhandling. Dette gjør det enklere å utvikle tjenester som bygger på data og funksjonalitet fra flere virksomheter, og som oppleves mer sømløse for sluttbrukeren.
